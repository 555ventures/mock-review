# Deviations — 02-one-vite-per-host

- AC-20260916-02-3/4's Contracts fixture literally uses `root: '/h'`, which analysis/config.ts::loadConfig guards with a real `existsSync(<root>/mock.config.ts)` before ever calling the runner — a literal, non-existent `/h` would short-circuit to `NULL_CONFIG` regardless of the fake ssr runner, defeating AC-3's own "config.name is 'fake'" assertion, and this repo's tests have no existing `vi.mock('node:fs')` precedent to fake that check instead. AC-3's test uses a real `mkdtempSync` scratch root with a real (never-read) `mock.config.ts` placeholder in its place; AC-4 keeps the literal `/h` since its throw happens synchronously in `getRunner`, before any filesystem access. Also, AC-3's literal fixture config (`targets: [], client: null`) fails `ConfigSchema.strict()` outright (`targets` must be `{viewports,schemes}`, `client` must be `{token}`), which would degrade to `NULL_CONFIG` before ever reaching `config.name`; the test's fake config uses `targets: { viewports: [], schemes: [] }` and `client: { token: 'x' }` instead, preserving the AC's essential assertion (a non-instance ssr env reaches a loaded, non-null config) without also asserting an internally-inconsistent fixture literal.
- D6's locked regex (`/^\s*import\s+(?!type\b)[^;]*?\bfrom\s+['"]vite['"]/m`) false-positives across two adjacent import lines when applied to a whole file's source at once, because this repo's semicolon-free style lets the lazy `[^;]*?` span a newline: `src/server/watch.ts`'s `import path from 'node:path'` line (no `vite` at all) fuses with the very next line's real `import type { … } from 'vite'`, flagging watch.ts as a 4th hit alongside the three the spec's own AC-11 illustration names. `tests/package/vite-imports.test.ts` applies the three D6 patterns per line (splitting each file's source on `\n` first) rather than to the whole file string, which reproduces exactly the spec's stated "today" result (`plugin.ts`, `vite-runner.ts`, `serve.ts`) and leaves `watch.ts` (untouched by this spec's File Plan, and never carrying a runtime `vite` import) out of the count.
- D9's `startHostVite` argv omits `--host`; on the installed vite 8.3.0, spawning `node_modules/vite/bin/vite.js --port <p> --strictPort` with no `--host` bound to `localhost` in a way that refused a direct IPv4 `127.0.0.1` connection outright (confirmed by manual repro — `curl` to `127.0.0.1:<port>` failed with connection-refused while the same request against `--host 127.0.0.1` succeeded), which would make AC-8/AC-9's own `GET http://127.0.0.1:<port>/...` requests fail for an infrastructure reason unrelated to the AC. `tests/helpers/cli.ts`'s `startHostVite` adds `'--host', '127.0.0.1'` to the spawned argv.
